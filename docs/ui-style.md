## 一、设计目标与风格判断

### 产品类型与体验目标

Xtrip 是无登录的旅行前规划 Demo：客户只跟规划经理 **Coco** 说话，看专员进度，再打开网页行程报告改卡片。最常做的事是**打字聊天**和**看一份按天报告**。设计要把中栏对话和底栏输入始终留住；右栏是灵感或地图，不是第二条聊天。报告不进 PDF、不整篇贴进气泡。

体验目标：**打开就像走进一间安静的深夜工作台**——底是整片深黑，角落有一点暖光，三栏不再各刷一块灰。内容（城市照片、地图、行程卡片、输入条边光）再给温度。

### 视觉风格

名称：**深夜对话工作台**。

- 整页深黑 `#050508`，左上暖金光、右上极淡紫晕，底层铺 React Bits Galaxy 星空（`saturation: 0`，指针会推开星星）。三栏透明，靠分割线分开，不再各刷一块灰。
- 主按钮仍是白底黑字，没有品牌彩条，不套黄紫渐变键。
- 对话区：Coco 消息几乎无气泡，用户消息略抬起的深色圆角块；输入条贴中栏底部。
- 三栏比例像旅行规划工作台：左导航窄、中对话宽、右栏看图/看地图，可用左侧细条拖动改宽。
- 避免：把紫粉渐变铺满壳子或主按钮、绿色发送键、旅游站大红大绿、玻璃拟态堆叠、Mindtrip 字标、复制参考站登录页。
- 例外：灵感卡、行程卡、对话输入条（中栏与详情侧栏）使用 Border Glow。网格色 `#c084fc` / `#f472b6` / `#38bdf8`，外侧光晕 HSL `40 80 80`。卡片：指针靠近边缘才亮。输入条：点进输入后边光沿边框持续转动，失焦后收回。不包整页、气泡、列表行或导航。
- 内容可用少量旅行 emoji 当标记（景点 📍、住宿 🏨、公交 🚌、预算 💰），壳子仍黑白；一条回复只领 1 个 emoji，不当彩绘贴纸墙。

### 关键 UX 规则

1. **输入永不被挤掉**：中栏（及详情侧栏）消息区滚动，composer 固定底部。对应 UI-001/002/005。
2. **当前页互斥**：对话 / 行程列表 / 行程详情同一时刻只显示一个主区；隐藏页 `display:none`，不占位。刷新后 URL、选中导航、内容一致。无登录。
3. **状态写在对话里**：追问、规划中、失败原因、方案已好，都是 Coco 的消息，不用整页弹窗代替。失败必须出现原因（AC-004）。
4. **主操作一个**：发送、创建计划、查看行程，当前状态只突出一个实心白按钮。
5. **专员不是三个聊天对象**：过程是中栏一块可展开的运行日志，客户不能点进去给专员下指令；只能点日志步骤看只读细节。
6. **长内容截断**：侧栏会话标题单行省略；灵感描述最多两行；卡片标题单行，介绍两行。

## 二、全局视觉系统

### 配色方案

暗色为主题，无第二套浅色（本期不做）。

| 名称 | 色值 | 用途 | 适用 |

文字与背景：`text.primary` 仅用在 `bg.app/sidebar/main/panel/elevated` 上。`cta.bg` 上只用 `text.inverse`。焦点环：`border.strong` 1px + 外扩 2px 半透明白。禁用降低到 40% 不透明度，仍可读。

灵感卡片上的照片可以是彩色；城市名、推荐理由和描述只写在图下独立文案区，用上表文字色，不叠到照片上。不要给照片加品牌色滤镜。

### 字体与字阶

| 用途 | 字体与回退 | 字号 | 字重 | 行高 / 字距 |
| --- | --- | --- | --- | --- |
| 产品名 Xtrip | `Inter`, `ui-sans-serif`, `system-ui`, 无衬线 | 18px | 600 | 1.2 / 0.02em |
| 页面/区块标题 | `"PingFang SC"`, `"Hiragino Sans GB"`, `"Noto Sans SC"`, `"Microsoft YaHei"`, sans-serif | 20px | 600 | 1.3 |
| 对话正文、表单 | 同上，英文数字跟 Inter | 16px | 400 | 1.55 |
| Coco / 用户名 | 同上 | 13px | 500 | 1.3 |
| 辅助、交通、时间 | 同上 | 13px | 400 | 1.4 |
| 日期 chip、标签 | 同上 | 13px | 500 | 1.2 |
| 占位符 | 同上 | 16px | 400 | 1.5 |

中英混排不强制等宽。无代码块。768 以下对话正文可维持 16px，避免输入缩放。字体不可用时走系统无衬线，不引入未授权的 ChatGPT 商业字体。

### 布局、间距与形状

间距刻度：4 / 8 / 12 / 16 / 24 / 32。

| 项 | 值 |
| --- | --- |
| 左侧栏宽 | 260px；折叠为 64px 仅图标（≥1280 可手动折叠，默认展开） |
| 右栏宽 | 默认 400px（灵感/地图），桌面可拖左缘分隔条，范围 280–720px，本机记住；双击或回车恢复默认。详情页侧栏对话 360px |
| 列间距 | 0（用 `border.subtle` 分隔，不要大空隙把工作台拆散） |
| 页边 | 侧栏内 12px；中栏消息左右 24px，最大阅读宽 760px 居中 |
| composer 高 | 内容自适应，最小 52px，最大约 160px 后内部滚动 |
| 导航项高 | 40px，圆角 10px |
| 主按钮高 | 36px（工具条）/ 40px（弹层主操作） |
| 圆角 | 控件 10px；用户气泡 18px；卡片 14px；弹层 16px；头像 50% |
| 工作台高 | `100vh`；顶无独立顶栏，产品名在侧栏顶部 |

响应式：

- ≥1280：三栏同时可见。
- 1100–1279：三栏仍可见，右栏沿用用户拖过的宽度。
- <1100：右栏改为覆盖层，中栏全宽；地图/灵感用右上角「地图 / 灵感」打开。
- <768：侧栏抽屉；新建计划弹层全宽贴底。

### 层次、阴影与动效

层次靠整页深黑 + Galaxy 星空 + 角落氛围光，三栏不再靠大块灰底区分。弹层：`overlay` + `#0c0c12`，阴影 `0 16px 48px rgba(0,0,0,0.45)`。普通表面仍靠 1px `border.subtle`。灵感卡 / 行程卡 / 输入条的 Border Glow 底色保持 `#2f2f2f`，本轮不改发光逻辑。`prefers-reduced-motion: reduce` 时星空静止。

动效：消息出现 160ms 淡入；弹层 180ms；专员行状态切换无弹跳。卡片边光跟随指针，不做循环扫光。输入条在聚焦输入时边光沿边框匀速转动（约 6 秒一圈），失焦停止。`prefers-reduced-motion: reduce` 时全部瞬时，边光关闭，只留细边。规划中专员用细环旋转（白，1s 匀速），不是彩色波纹。

### UI-001 规划前工作台

- **依据与目标**：打开即用。左菜单、中可聊、右灵感图+短文。点灵感不进详情、不开新行程。原型 `#p-home`。
- **布局结构**：三栏。中栏垂直：上空白弹性区 + 居中欢迎（产品名可不再重复，一句「和 Coco 规划一趟旅行」）+ 底 composer。右栏顶「灵感」+ 可滚动卡片。滚动只发生在中栏消息（空时不滚）和右栏卡片。composer 不随滚动离开视口。
- **内容呈现**：灵感卡照片保持干净，不在图上叠字（亮部/暗部都会看不清）。图下独立文案区（`bg.elevated`）：城市名 13px 600 先标明是哪座城，推荐理由（title）16px 600，描述 13px 最多两行。至少 3 张以看出重复。
- **组件清单**：

| 区域 | 组件 | 内容/数据 | 交互 | 风格 |
| --- | --- | --- | --- | --- |
| 左 | 导航 | 对话（选中）、行程、新建计划 | 点行程→UI-004；点新建→UI-003 | 侧栏项 |
| 中 | 欢迎 + composer | 占位「从上海出发去杭州，轻松 5 天…」 | 空内容发送禁用 | 主按钮在输入右侧圆角方钮 |
| 右 | 灵感卡 | 杭州 / 成都 / 大理 等国内（演示）；每张可见城市 + 推荐理由 + 短描述 | 点击无跳转；指针靠近边缘边光跟随 | 彩图；字只在图下；紫粉蓝 Border Glow |

- **状态与操作结果**：
  - 空工作台 → 发第一条出行消息 → 进入 UI-002，右栏换成地图（AC-013）。
  - 点灵感卡 → 仍停在 UI-001（AC-020）。
  - 刷新 → 仍在对话页、无登录墙。
- **示例数据（仅演示）**：杭州 / 西湖边慢慢走 / 湖景、茶、短途高铁都合适；成都 / 熊猫与火锅 / 节奏可以很慢；大理 / 风大，适合发呆 / 洱海边发呆就够了。
- **页面例外**：无。

### UI-002 对话与规划中

- **依据与目标**：问诊、运行日志可见、步骤可点开细节、失败讲原因、成功给详情入口。右栏地图。AC-001～004,011,013,024。
- **布局结构**：同三栏。中栏上为消息列表（滚），下 composer。规划中在 Coco 消息下插入**可展开运行日志**（摘要行 + 步骤列表），不另开抽屉、不做第三条聊天。
- **内容呈现**：用户右气泡；Coco 左裸文。日志用 muted 逐步句，不要做成三个专员气泡。长列表在中栏滚动，输入条不动。
- **组件清单**：消息、运行日志、日志细节弹窗、composer、地图槽。
- **状态与操作结果**：
  - 最小集未齐 → Coco 一轮问完缺口，无运行日志（AC-002）。
  - 已齐 → Coco「开始出方案」+ 日志出现并逐条增加（AC-001,003）。规划中再发送：Coco 回「专员还在做」，不新开任务。
  - 2 轮仍缺 → Coco 说明缺口，无按天方案（AC-011）。
  - 点带结果的步骤 → 弹窗细节，关后仍在对话（AC-024）。
  - 研究失败 → 日志保留失败步，Coco 写出原因，无「查看行程」（AC-004）。
  - 成功 → Coco 告知可看报告 + 主按钮「查看行程」→ UI-005。日志可收起回看。
  - 地图无 Key → 右栏文案「地图未配置」，对话照常。
- **示例数据**：摘要「规划中 · 已查 6 处地点、3 次路线」。步骤：「查询杭州地理编码」「搜索景点 西湖」「思考 4s」「读取天气」「估算分类预算」「查询公交 灵隐寺 → 西湖」。点「搜索景点 西湖」弹窗正文：「找到：西湖、断桥、苏堤。」失败示例见 AC-004。
- **页面例外**：失败消息左侧加 2px 白条，仍用 Coco 口吻，不加红底。

### UI-003 新建计划

- **依据与目标**：预填去哪、何时、和谁、预算、节奏，缩小最小集（AC-014）。
- **布局结构**：模态，不跳新路由。标题「新建计划」，主按钮「开始聊」。遮罩点击关闭。
- **内容呈现**：纵向表单，标签在上。节奏三档为同等 chip，选中 `bg.selected`。
- **组件清单**：字段 去哪、何时、和谁（成人/儿童）、预算、节奏（轻松/适中/紧凑）、目前已知的计划（多行）、取消、开始聊。
- **状态与操作结果**：全空也可「开始聊」→ 进入对话，Coco 追问缺口。填了杭州 5 天等 → Coco 不再问已填节奏。不在弹层里直接出方案。
- **示例数据**：去哪杭州；何时 5 天；2 名成人；预算 20000；节奏轻松。
- **页面例外**：无。

### UI-004 行程列表

- **依据与目标**：从左侧进已生成行程（AC-015）。
- **布局结构**：左栏不变。中栏变为列表（全宽，右栏隐藏）。无灵感。
- **内容呈现**：每行标题、目的地城市、天数、节奏中文、更新时间。无缩略图拼贴。
- **组件清单**：列表行；空态「还没有行程，先和 Coco 聊一趟」。
- **状态与操作结果**：点一行 → UI-005 同一份方案。规划中的会话不出现在此列表（仅 `ready`）。
- **示例数据**：杭州 5 天 · 轻松 · 今天。
- **页面例外**：无。

### UI-005 行程详情

- **依据与目标**：网页报告：日期滚动、卡片、交通、预算、清单、微详情、侧边 Coco、快捷建议。非 PDF。
- **布局结构**：左导航；中报告（顶栏固定：标题+日期 chip+「地图模式」次按钮，`bg.main` 铺满并带底部分割线，滚动时内容不从标题下透出；下：可滚内容：预算摘要、行前清单、按天卡片）；右 360px Coco + 底 composer + 输入上方纵向 chip 建议。中栏滚、右栏消息另滚，互不挤压输入。标题栏不随报告滚动。
- **内容呈现**：每天先日期小标题，再卡片；卡间交通条。预算：合计 + 是否超出（文字「超出上限」，不用大红块）。清单：checkbox 仅展示，本期不要求持久勾选也可（若实现则刷新仍在本机）。地图模式：中栏换成地图，卡片缩为左侧或底部条，点位与当天一致。
- **组件清单**：日期 chip、行程卡（Border Glow）、交通条、微详情模态、快捷建议、侧聊。
- **状态与操作结果**：
  - 滚到第 3 天 → 第 3 天 chip 高亮；点 chip 滚到当天（AC-021）。
  - 点卡片 → 微详情（名、短介绍、地址，无支付）（AC-023）。
  - 删第 2 天某点 → 列表与地图当天点消失，专员状态保持已完成（AC-006,017）。
  - 侧边说「第三天不要排那么满」或点建议 → 该句进入用户气泡，建议 chip 全部收起，同一份报告变松（AC-018,019）。
  - 换目的地类大改 → Coco 请去新建计划，本页卡片不变。
- **示例数据**：杭州 5 天情侣轻松。第 1 天：灵隐寺 → 交通「公交约 25 分钟」→ 西湖。预算合计约 1.6 万，上限 2 万。清单：身份证、轻便外套。建议 chip：「第三天少排一点」「把住宿换到湖边」。
- **页面例外**：微详情图可以彩色；壳子仍黑白。
